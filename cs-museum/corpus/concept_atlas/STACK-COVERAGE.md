# Bedrock-to-HCI coverage boundary

The report names a vertical route from human/business concerns through software, system design, programming/runtime, networking, computer architecture, theory/math, digital logic and electronics. Naming a layer is not the same as supplying lessons at that layer. The current release is a **language-concept atlas with selected stack traces**, not a full-depth curriculum for every layer.

| Layer named by the report | Current release evidence | Closure status |
|---|---|---|
| Human/business and product context | Innovation strategy and learning hypothesis | Context only; no validated pedagogy or domain curriculum |
| HCI/UX and accessibility | Architecture contracts, DOM reader requirement, WAI references | Contract specified; implementation and usability evidence open |
| Software engineering | Problem/solution/cost records and assessment fields | In scope; many records still scaffold/source-unknown |
| System design | API, versioning, failure and trade-off contracts | Selected architecture cases; broad design mastery not claimed |
| Programming language concepts | 200 records across14 clusters and26 columns | Primary release scope; source promotion incomplete |
| Runtime, OS and networking | Selected event-loop, ABI, deployment and integration examples | Supporting traces; not an OS/networking syllabus |
| Computer architecture, theory and math | Claims about caches, registers, IR and execution substrate | Illustrative connections; dedicated depth records remain open |
| Digital logic, electronics and semiconductor physics | Mentioned as endpoint examples in the narrative | Not covered at lesson granularity in this release |

## Depth definition

A layer is “covered deeply” only when its records include a concrete problem, formal or operational mechanism, worked trace, competing solution, cost, boundary counterexample, source evidence and an unfamiliar transfer assessment. A layer can be present as a cross-layer edge without satisfying that test. The generated records and learning plan enforce this distinction.

## Expansion path

If bedrock-to-HCI coverage is a product requirement, add versioned layer clusters and records without changing existing concept IDs: logic/electronics, architecture/memory hierarchy, OS/processes, networking/protocols, distributed systems, security, HCI/accessibility and pedagogy. Give each its own denominator and source registry. Do not claim the current language corpus closes those layers by analogy.
