# Planning Audit — Mistakes, Root Causes & Two-Level Fixes

Companion to `SPEC.md`. Full audit of the 90-day plan v1. Each mistake is traced to a root cause, fixed at the **instance** level (the specific schedule) and prevented at the **systemic** level (a SPEC capability + a pedagogy rule).

## Root Causes (why the mistakes happened)

The plan was generated by a naive model, not by learning science + candidate reality. Five root causes:

| ID | Root Cause | The flawed assumption |
|----|-----------|----------------------|
| **RC-A** | **Linear-Phase fallacy** | "Schedule topics as sequential blocks in list order." Ignores that skills have different *cadences* (continuous vs sprint) and *lead times*. |
| **RC-B** | **First-pass = done fallacy** | "Once taught, it's learned." Ignores memory decay; SM2 spaced-repetition state was declared in okf but never scheduled. |
| **RC-C** | **Blank-slate fallacy** | "Candidate is weak everywhere." Ignored verified breadth + 2026 market. *(Mostly fixed in the 2026-07-22 correct-course.)* |
| **RC-D** | **Optimistic-packing fallacy** | "Every week runs at 100%, nothing slips." No buffer; long-lead human items placed as a finale. |
| **RC-E** | **State/plan divergence** | Pedagogy rules and the weekly plan were written separately and contradict each other. |

## Two-Level Fix Principle

- **Instance level** = correct the specific dates in `90DAY_LEARNING_PLAN.md` / `okf_state.json`.
- **Systemic level** = the nine invariants in `SPEC.md` (so a re-derived plan can't reproduce the mistake) **plus** teach-me `SKILL.md` pedagogy rules that enforce cadence-aware scheduling, spaced review, and long-lead nurture.

## Verification Checklist (run against any plan)

- [ ] Every skill has a cadence tag; no continuous skill is a late block. *(CAP-1)*
- [ ] No weak+slow+gated skill starts after Week 2. *(CAP-2)*
- [ ] SQL, DSA, Core CS each have a post-sprint review + pre-interview re-check. *(CAP-3, CAP-4)*
- [ ] Referral nurture ≤ Week 2; pitch ≤ Week 3; interviews pursued as gates clear. *(CAP-5)*
- [ ] All six weaknesses scheduled; Math + HR have tracks. *(CAP-6)*
- [ ] System Design via bridge; AI + cloud tracks exist. *(CAP-7)*
- [ ] ≥ ~1 week buffer before interviews. *(CAP-8)*
- [ ] No okf/SKILL rule contradicts the plan. *(CAP-9)*
