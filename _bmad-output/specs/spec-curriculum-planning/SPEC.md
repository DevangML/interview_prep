It governs *scheduling and pedagogy invariants*, not lesson content. Any re-derived plan must satisfy every capability below.

# Curriculum Planning Invariants — 90-Day Interview Sprint

## Why

A **pain to solve.** The first 90-day plan was generated by a naive "linear-phase" mental model: list the topics, schedule them as sequential blocks, gate each once. That model repeatedly mis-scheduled skills — the clearest symptom being DSA (the weakest, slowest-building, hardest-gated skill) parked as a Week 2–4 block instead of a Day-1 habit. The same root causes produced a cluster of sibling mistakes (behavioral/referrals/math scheduled too late, no spaced review, one-time gates, no buffer, state/plan contradictions — see `planning-audit.md`). The learner is Devang: 2-yr engineer, real deadline (90 days, 30-day notice), verified strengths in Flutter/full-stack/AI and genuine gaps in DSA/SQL/CS/System-Design-articulation. Fixing individual dates is not enough; the *generator* must be constrained so the mistake-class cannot recur on the next re-plan.

## Capabilities

- **CAP-1**
  - **intent:** The planner classifies every skill by cadence — *continuous* (daily drip), *sprint* (focused block), or *long-lead* (start early, nurture) — and schedules by that cadence rather than by list order.
  - **success:** Every skill in the plan carries a cadence tag; no continuous-cadence skill appears as a single late block.
- **CAP-2**
  - **intent:** The weakest × slowest-building × hardest-gated skills start on Day 1 with the longest runway.
  - **success:** No bottom-quartile-mastery, hard-interview-gate skill starts after Week 2; DSA starts Day 1.
- **CAP-3**
  - **intent:** Every weak skill gets scheduled spaced reviews (SM2) after its first pass — nothing is "learned once."
  - **success:** SQL, DSA, and Core CS each have ≥1 post-sprint review checkpoint plus a pre-interview re-verification.
- **CAP-4**
  - **intent:** Assessment gates are achieve-**and**-maintain, re-verified before interviews.
  - **success:** A gate-maintenance re-check in the final fortnight covers every earlier gate.
- **CAP-5**
  - **intent:** Long-lead, human-dependent items (warm-network referrals, interview scheduling) start early and run in parallel, not as a finale.
  - **success:** Referral nurture begins ≤ Week 2; a usable elevator pitch exists ≤ Week 3; interviews are pursued as gates clear, not deferred to Week 12.
- **CAP-6**
  - **intent:** Every stated weakness has an explicit, scheduled home in the plan.
  - **success:** None of {DSA, SQL, Core CS, Math/Numericals, System Design, HR/Selling} is unscheduled; Math/Numericals and HR each have a track.
- **CAP-7**
  - **intent:** The plan leverages Devang's verified breadth (Experience Bridge) and weights effort toward 2026-paying skills.
  - **success:** System Design is taught via the bridge (not from scratch); an AI-integration track and a cloud-fundamentals track both exist.
- **CAP-8**
  - **intent:** The plan reserves slack for real-world slippage.
  - **success:** ≥ ~1 week-equivalent of buffer / lighter consolidation load exists before the interview window.
- **CAP-9**
  - **intent:** The pedagogy rules (okf_state.json, teach-me SKILL.md) and the weekly plan do not contradict each other.
  - **success:** No rule states an ordering the plan violates (e.g., the Referral Readiness Protocol wording is reconciled with the SQL+DSA-first order).

## Constraints

- Fixed 90-day window + 30-day notice period — a real deadline; the plan must fit **and** leave buffer.
- Interviews hard-gate on DSA / SQL / Core CS regardless of real-world engineering strength — no Experience-Bridge substitute for these three.
- Finite daily time budget — continuous tracks must stay small (e.g., DSA ≤ ~45 min/day) so running several in parallel is survivable.
- The teach-me flow stays curate-and-test, never lecture — the token-efficient pedagogy is carried, not replaced.

## Non-goals

- Not a content/lesson library — this contract governs scheduling and pedagogy invariants only.
- Not converting DSA or SQL into "bridged" topics — they stay ground-up, from fundamentals.
- Not maximizing Flutter depth — already strong and commoditized; maintain, don't grind.
- Not a generic plan for other candidates — tuned to Devang's verified profile and deadline.

## Success signal

Running the `planning-audit.md` checklist against a re-derived 90-day plan yields **zero violations**: DSA/behavioral/referral-nurture all start Day-1 or early, every stated weakness has a scheduled home, spaced reviews and a pre-interview gate-maintenance pass exist, a buffer is present, and no okf/SKILL rule contradicts the weekly plan.
